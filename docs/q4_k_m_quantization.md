# Q4_K_M 量化详解：权重 W 是怎么被压成 4 bit、又还原回来的

> 本文以 llama.cpp 的 k-quants 实现为准（`block_q4_K`、`block_q6_K`）。
> 文中所有数值都可以按给出的公式手算复核。

---

## 0. 一句话概括

Q4_K_M 不是"把每个权重四舍五入成 4 bit"，而是：

1. 把 256 个权重组成一个 **super-block**，再切成 8 个 **32 权重的子块**；
2. 每个子块用一条仿射直线 `W ≈ step × q + lo` 去拟合（`lo` 是子块最小值），`q` 只存 4 bit；
3. 每条直线的 `step` 和 `min` 本身又被压成"6 bit 码 × FP16 基准"；
4. 少数敏感张量（输出层、一半的 `attn_v` / `ffn_down`）改用 6 bit 的 Q6_K。

最终整个模型平均约 **5 bit/权重**，而文件里的 4-bit 字段只是其中一层。

---

## 1. 名字拆开

| 片段 | 含义 |
|---|---|
| `Q4` | 权重主体用 4 bit 存，每 32 个权重一组量化 |
| `K` | k-quants 家族，使用 256 权重的 super-block 和分层的 scale |
| `M` | Medium，混合精度配方：大部分张量 Q4_K，少数敏感张量升到 Q6_K |

同一宽度下还有更小的 `Q4_K_S`（全部 Q4_K）。`S / M` 的区别不是位宽，而是"哪些张量被特殊照顾"。

---

## 2. 一个容易误解的点：Q4 不等于 4 bit/权重

一个 `block_q4_K` 固定描述 256 个权重，占用 144 字节：

| 字段 | 字节数 | 作用 | 折算 bit/权重 |
|---|---|---|---|
| `d` | 2 | FP16，所有 6-bit scale 的公共基准 | 16 / 256 = 0.0625 |
| `dmin` | 2 | FP16，所有 6-bit min 的公共基准 | 16 / 256 = 0.0625 |
| `scales[12]` | 12 | 8 个 scale 码 + 8 个 min 码，各 6 bit | 96 / 256 = 0.375 |
| `qs[128]` | 128 | 256 个 4-bit 量化码 | 1024 / 256 = 4.0 |
| **合计** | **144** | | **4.5** |

所以"纯 Q4_K"的实际成本是 **4.5 bit/权重**，不是 4.0。

本项目最终产物是 **4.99 bit/权重**，比 4.5 更高，原因见第 8 节（Q6_K 张量和 F32 norm）。

## 3. 数据布局

### 3.1 super-block 与 sub-block

```
一个 super-block = 256 个权重
├── 子块 0：权重   0.. 31   → scale[0], min[0]
├── 子块 1：权重  32.. 63   → scale[1], min[1]
├── ...
└── 子块 7：权重 224..255   → scale[7], min[7]
```

每个子块共享一对 `(step, min)`，但这 8 对不是直接存 FP32，而是共用两个 FP16 基准 `d`、`dmin`，各自只存 6 bit 的比值。

### 3.2 6 bit 的 scale / min 怎么塞进 12 字节

8 个 scale × 6 bit = 48 bit = 6 字节；8 个 min × 6 bit = 48 bit = 6 字节。

解包函数（llama.cpp 的 `get_scale_min_k4`）是：

```c
// j = 0..7，取出第 j 个子块的 6-bit scale 码 sc 和 min 码 m
if (j < 4) {
    sc = q[j]     & 63;   // 字节 0..3 的低 6 位
    m  = q[j + 4] & 63;   // 字节 4..7 的低 6 位
} else {
    sc = (q[j + 4] & 0x0F) | ((q[j - 4] >> 6) << 4);
    m  = (q[j + 4] >> 4)   | ((q[j]     >> 6) << 4);
}
```

前 4 个码放在低 6 位，后 4 个码用"低 4 位 + 前面字节的高 2 位"拼出来。
不关心位序也不影响理解公式，只需知道：**每个子块有一个 0..63 的 scale 码和一个 0..63 的 min 码**。

### 3.3 4-bit 的 q 怎么排

`qs[128]` 中每 32 字节描述 64 个权重，采用 nibble 交错：

```
字节 k 的低 4 位 → 第 k 个权重
字节 k 的高 4 位 → 第 32 + k 个权重
```

也就是说，`qs` 的字节顺序不是权重顺序：前 32 个权重在一个字节的低半字节里，接下来 32 个在该字节的高半字节里。解码时每 64 个权重处理一次：

```c
for (j = 0; j < 256; j += 64) {
    (sc0, m0) = get_scale_min_k4(is + 0);   // 低半字节对应的子块
    (sc1, m1) = get_scale_min_k4(is + 1);   // 高半字节对应的子块
    for (l = 0; l < 32; ++l)
        y[j + l]      = (d * sc0) * (qs[l] & 0x0F) - (dmin * m0);
    for (l = 0; l < 32; ++l)
        y[j + 32 + l] = (d * sc1) * (qs[l] >> 4)   - (dmin * m1);
    qs += 32;
    is += 2;
}
```

## 4. 编码：从浮点 W 到 4-bit q

先统一记号：

| 符号 | 含义 | 精度 |
|---|---|---|
| `W` | 张量里的一个真实浮点权重 | FP32/FP16 |
| `q` | 该权重的 4-bit 码 | 0..15 |
| `step` | 子块的量化步长 | 浮点 |
| `offset` | 子块的零点偏移（正数） | 浮点 |
| `d` | 所有 scale 码的公共基准 | FP16 |
| `sc` | 子块的 scale 码 | 6 bit，0..63 |
| `dmin` | 所有 min 码的公共基准 | FP16 |
| `m` | 子块的 min 码 | 6 bit，0..63 |

记某子块内 32 个真实权重为 `W_0 ... W_31`。

### 4.1 第一层：子块内的仿射拟合

取这 32 个数的真实最小值和最大值：

```
lo = min(W_i)
hi = max(W_i)

step   = (hi - lo) / 15        // 把区间均分成 15 段，得到 16 个格子
offset = -lo                   // 正数，表示"零点偏移"
```

于是重构规则是：

```
W' = step × q + lo
   = step × q - offset
```

其中 `q ∈ [0, 15]`。`q = 0` 对应最小值 `lo`，`q = 15` 对应最大值 `hi`。

编码时反解：

```
q = clamp( round( (W - lo) / step ), 0, 15 )
  = clamp( round( (W + offset) / step ), 0, 15 )
```

### 4.2 第二层：把 step 和 offset 压成 6 bit

8 个子块各自算出一组 `(step_j, offset_j)`，然后：

```
d    = max_j(step_j)   / 63     // 存 FP16
sc_j = round(step_j   / d)      // 6 bit，0..63

dmin = max_j(offset_j) / 63     // 存 FP16
m_j  = round(offset_j / dmin)   // 6 bit，0..63
```

解码时还原：

```
step_j   ≈ d    × sc_j
offset_j ≈ dmin × m_j
```

注意 `d` 不是步长本身，而是"步长的公共缩放"；真正乘在 `q` 上的是 `d × sc_j`。

### 4.3 第三层：每个权重取整

```
q_i = clamp( round( (W_i + dmin × m_j) / (d × sc_j) ), 0, 15 )
```

实际实现（`make_qkx2_quants`）不是简单取 min/max，而会迭代搜索一组让加权误差最小的 `(step, offset)`，但形式仍然是上面这条仿射直线。

---

## 5. 解码：W' 的计算公式

对第 `j` 个子块里的第 `i` 个权重：

```
W'_i = (d × sc_j) × q_i - (dmin × m_j)
```

展开成三层看：

```
     ┌─ super-block 基准 ─┐   ┌─ 子块码 ─┐   ┌ 权重码 ┐   ┌─ 子块 min ─┐
W' = (        d           ×     sc_j    ) ×    q_i    - (    dmin      ×   m_j )
```

**为什么是减号：** `m_j` 存的是正的偏移量 `-lo`。真实最小值是 `lo = -offset`，所以 `step × q + lo = step × q - offset`。存正、还原时减。

推理时通常不会先把整个张量反量化成 FP32 再算，而是在矩阵乘的 kernel 里按块即时反量化（或直接用整数点积）。上面这个 `W'` 就是 kernel 眼中"这个权重是多少"。

## 6. 完整手算例子：一个 32 权重的子块

### 6.1 设定

假设某个子块的真实权重是一条从 -0.12 到 0.50、步长 0.02 的等差数列（正好 32 个数）：

```
W_i = -0.12 + 0.02 × i,    i = 0..31
```

于是：

```
lo = -0.12
hi =  0.50
step   = (0.50 - (-0.12)) / 15 = 0.62 / 15 = 0.0413333...
offset = 0.12
```

编码规则：

```
q_i = round( (W_i + 0.12) / 0.0413333 )
    = round( 0.02 × i / 0.0413333 )
    = round( 0.483871 × i )

W'_i = 0.0413333 × q_i - 0.12
```

因为 `0.02 / 0.0413333 = 0.4839 < 0.5`，相邻两个原始权重会落进同一个格子：`q` 的模式是 `0,0,1,1,2,2,...,15,15`。

### 6.3 从表里能读出什么

1. **两个真实值共用一个 q。** 例如 `W_0 = -0.12` 和 `W_1 = -0.10` 都是 `q = 0`，还原后都变成 `-0.12`。
2. **误差上限是半个 step。** 本例子 `step/2 = 0.020667`，表里最大误差 0.0200，没有越界。
3. **误差有方向。** 因为 `0.02/step = 0.4839` 略小于 0.5，偶数下标的误差逐渐变正、奇数下标逐渐变负，在两端达到 ±0.02。
4. **只有 16 个可取值。** 32 个权重最终只落在 16 个重建点上，这就是 4 bit 的真实含义。

如果原始权重恰好落在

```
{-0.12 + 0.0413333 × k | k = 0..15}
```

这些点上，误差会全是 0；现实中的权重不会这么巧，所以总会有舍入误差。

### 6.4 加上第二层：6-bit 的 scale / min 量化

上面的 `step = 0.0413333`、`offset = 0.12` 还不能直接存，它们要和同一个 super-block 里的另外 7 组一起压成 6 bit。

**情形 A：本子块正好是 8 组里的最大值。**

```
d    = 0.0413333 / 63 = 0.000656085     (FP16)
sc   = 63
step' = d × sc = 0.0413333               // 无损

假设 8 组里最大 offset 是 0.18：
dmin = 0.18 / 63 = 0.00285714            (FP16)
m    = round(0.12 / 0.00285714) = 42
offset' = dmin × m = 0.00285714 × 42 = 0.12   // 本例子正好无损
```

此时最终公式仍是：

```
W' = 0.0413333 × q - 0.12
```

误差全部来自 4-bit 取整。

**情形 B：别的子块步长更大。**

假设 8 组里最大 `step` 是 0.05，最大 `offset` 是 0.20：

```
d    = 0.05 / 63      = 0.000793651
sc   = round(0.0413333 / 0.000793651) = round(52.0833) = 52
step' = 0.000793651 × 52 = 0.0412698     // 相对误差 -0.154%

dmin = 0.20 / 63      = 0.00317460
m    = round(0.12 / 0.00317460) = round(37.8) = 38
offset' = 0.00317460 × 38 = 0.120635     // 绝对误差 +0.000635
```

最终公式变成：

```
W' = 0.0412698 × q - 0.120635
```

对 `q = 15`：

```
W' = 0.0412698 × 15 - 0.120635 = 0.498413
真实值 0.5000，误差 -0.001587
```

也就是说，第二层量化只带来约 **0.0016 量级**的额外误差，比 4-bit 的 ±0.02 小一个数量级。这就是为什么 Q4_K 的重点是"少存 scale"，而不是"把 scale 存得多准"。

### 6.5 误差预算

对单个权重，总误差大致由三部分组成：

| 来源 | 量级（本例） |
|---|---|
| 4-bit 取整 | ≤ step/2 = 0.0207 |
| 6-bit 重算 step | ≈ abs(Δstep) × q ≈ 0.0000635 × 15 ≈ 0.00095 |
| 6-bit 重算 offset | ≈ 0.0006 |
| FP16 存 d / dmin | 相对 ~1e-3，绝对可忽略 |

实际误差可能相互抵消，最坏情况约 0.0223，仍远小于一个原始权重的量级。

## 7. 为什么需要 min，以及离群点为什么可怕

### 7.1 全是正数的子块

假设某子块范围是 `[0.10, 0.58]`：

- **带 offset（Q4_K 的做法）**：
  ```
  step = (0.58 - 0.10) / 15 = 0.032
  最大误差 ≤ 0.016
  ```
- **不带 offset 的对称量化（Q4_0 一类，q 为 -8..7）**：
  ```
  有效步长 ≈ max(|W|) / 7 ≈ 0.58 / 7 ≈ 0.0829
  最大误差 ≈ 0.041
  ```

同样 4 bit，带 offset 的有效精度高约 2.5 倍，因为 16 个格子全铺在真实区间上，没有浪费负半轴。

### 7.2 一个离群点拖垮整组

还是 `[-0.12, 0.50]` 这个子块，但把其中一个权重改成 `0.90`：

```
step = (0.90 - (-0.12)) / 15 = 1.02 / 15 = 0.068
最大误差 ≤ 0.034
```

其余 31 个正常权重的精度从 0.0207 掉到 0.034，只因为一个离群点。

这解释了两件事：

1. **为什么子块是 32 个而不是 256 个**——块越小，离群点影响的范围越小，代价是 scale/min 的元数据更多（4.5 bit 里占了 0.5）。
2. **为什么 imatrix 有用**——它按"这个权重对输出有多重要"来加权选择 scale，而不是只看最大最小值；重要权重得到的误差更小。

## 8. Q4_K_M 的 M：哪些张量被升到 6 bit

llama.cpp 在 `Q4_K_M` 下不是所有张量都用 Q4_K。以本项目 4 层 draft 模型（build 11424）的实际日志为例：

| 张量 | 实际类型 |
|---|---|
| `output.weight`（lm_head） | **Q6_K** |
| `token_embd.weight` | Q4_K |
| `attn_q` / `attn_k` / `attn_output` | Q4_K |
| `attn_v`：blk.0 / blk.1 | Q4_K |
| `attn_v`：blk.2 / blk.3 | **Q6_K** |
| `ffn_gate` / `ffn_up` | Q4_K |
| `ffn_down`：blk.0 / blk.1 | Q4_K |
| `ffn_down`：blk.2 / blk.3 | **Q6_K** |
| 所有 norm 权重 | F32 不动 |

规律是：**输出层、一半的 `attn_v`、一半的 `ffn_down` 用 Q6_K，其余用 Q4_K。**

### 8.1 为什么平均是 4.99 bit 而不是 4.5

Q6_K 的 block 是 210 字节 / 256 权重 = **6.5625 bit/权重**。

本项目 4,162,816 个参数中：

| 部分 | 参数量 | 位宽 |
|---|---:|---:|
| Q6_K 张量（output + 2×attn_v + 2×ffn_down） | 966,144 | 6.5625 |
| Q4_K 张量 | 3,194,368 | 4.5 |
| F32 norm | 2,304 | 32 |

```
平均 = (966,144×6.5625 + 3,194,368×4.5 + 2,304×32) / 4,162,816
     = 20,788,704 / 4,162,816
     = 4.9938 bit/权重
```

和 `llama-quantize` 日志里的 `4.99 BPW` 完全对上：

```
F16:    16.01 BPW,  7.94 MiB
Q4_K_M:  4.99 BPW,  2.48 MiB
压缩比:  4.99 / 16.01 ≈ 31.2%，约 3.2×
```

### 8.2 Q6_K 为什么更准

Q6_K 的结构不同：

- super-block 仍是 256 个权重；
- 子块缩小到 **16 个权重**，每个子块一个 **int8 scale**；
- 每个权重用 **6 bit 有符号数**（-32..31）；
- 重建公式是 `W' = d × sc × q`（没有独立的 min 字段，靠有符号 q 覆盖负值）；
- 成本 210 字节 / 256 权重 = 6.5625 bit。

子块更小 + scale 有 8 bit 精度，是 Q6_K 比 Q4_K 明显更准、也更占空间的原因。

## 10. 常见问题

**Q：反量化得到的 W' 和原始 W 一样吗？**

不一样。Q4_K 是有损压缩，单个权重的误差上限约为子块步长的一半。上面例子里是 ±0.02。

**Q：推理时真的会把每个权重都乘回来吗？**

概念上是。实现上，ffn/attention 的 kernel 会按 block 即时反量化，或者直接用整数点积再乘 scale；不会先把整个模型展开成 FP32 再算。这样省的正是"读 16 bit 权重"的带宽。

**Q：Q4_K_M 和 Q4_K_S 差在哪？**

- `Q4_K_S`：所有张量都用 Q4_K，约 4.5 bit/权重；
- `Q4_K_M`：大部分 Q4_K，输出层、一半 `attn_v`、一半 `ffn_down` 用 Q6_K，约 5 bit/权重。

所以 M 比 S 略大，但质量更好。本项目的实际文件：Q4_K_S 2.61 MB，Q4_K_M 2.71 MB。

**Q：为什么不是正好 1/4 大小？**

因为 4 bit 只是 `q` 字段。scale/min、FP16 基准、Q6_K 张量和 F32 norm 都要占空间，平均下来是 4.99 bit，相对 F16 的 16 bit 是 31%，不是 25%。

**Q：对模型维度有要求吗？**

K-quants 的 block 是 256 个权重，要求被量化的那一维长度是 256 的倍数。本项目的 `hidden_size` 是 256（draft）或 512（target），正好满足：draft 每行一个 super-block，target 每行两个。

**Q：量化会改变模型结构吗？**

不会。层数、hidden、注意力头数、tokenizer 都不变，变的只是 GGUF 里权重张量的存储类型（`Q4_K` / `Q6_K` / `F32`）。加载后 llama.cpp 仍按 llama 架构前向。

## 附录 A：符号速查

```
q_i    第 i 个权重的 4-bit 码           0..15
sc_j   第 j 个子块的 6-bit scale 码     0..63
m_j    第 j 个子块的 6-bit min 码       0..63
d      所有 sc 的 FP16 公共基准
dmin   所有 m 的 FP16 公共基准

step_j   = d × sc_j
offset_j = dmin × m_j
W'_i     = step_j × q_i - offset_j
```

## 附录 B：编码 / 解码伪代码

### B.1 编码一个子块

```python
# W: 32 个真实权重
lo, hi = min(W), max(W)
step = (hi - lo) / 15
offset = -lo

q = [clamp(round((w + offset) / step), 0, 15) for w in W]

# 8 个子块都算完后，做第二层量化
step_basis = max(all_step) / 63
sc = [round(s / step_basis) for s in all_step]       # 6 bit

offset_basis = max(all_offset) / 63
mcodes = [round(o / offset_basis) for o in all_offset]  # 6 bit
```

### B.2 解码一个权重

```python
step_j = d * sc[j]
offset_j = dmin * m[j]

W_hat = step_j * q[i] - offset_j
# 等价于 step_j * q[i] + lo_j
```

### B.3 位宽核算

```
每 256 个权重:
  4 bit  × 256 = 1024 bit = 128 B
  6 bit  × 16  =   96 bit =  12 B   (8 个 scale + 8 个 min)
  FP16   × 2   =   32 bit =   4 B   (d + dmin)
  ------------------------------------
  合计 1152 bit = 144 B = 4.5 bit/权重
```
